# Научный метод — Ionogram Morphology Lab 1.1.1

Как IML разделяет evidence, интерпретацию и решение эксперта. Документ нормативен для пользовательских сценариев v1.1.1 и **не** заменяет протокол вашей организации.

## Обзор конвейера

```
импорт → профиль прибора → аудит качества → сырой рендер → сегментация
  → интерпретируемые признаки → правила с прослеживаемостью → сравнение с эталонами
  → разногласия / воздержание → решение эксперта (отдельная ось) → воспроизводимый экспорт
```

Каждый этап даёт **проверяемые артеfactы** с полями provenance. Этапы нельзя сводить к одной «диагностической» оценке.

## Отдельные научные оси

| Ось | Вопрос | Не путать с |
|-----|--------|-------------|
| Качество данных | Пригоден ли кадр? | Меткой морфологии |
| Видимая морфология | Какой шаблон виден на изображении? | Физическим механизмом |
| Неоднозначность | Какие альтернативы остаются? | Финальной классификацией |
| Помехи | Маскирует ли contamination traces? | Диагнозом неисправности прибора |
| Параметры | Какие численные оценки даёт метод? | Калиброванным ионосферным продуктом |
| Решение эксперта | Что зафиксировал рецензент? | Автоматической «истиной» |

Модификаторы морфологии по солнечному / dawn–dusk контексту в **IML-1 отключены**, чтобы не делать неявных суточных выводов только из метаданных.

## Кандидат vs валидированный результат

Автоматические выходы — **кандидаты** до экспертной проверки и внешней валидации по вашему протоколу:

- предложения пакетного анализа;
- срабатывания и воздержания правил;
- результаты скриптов MATLAB Studio;
- оценки классификатора Model Lab.

Статусы вроде `source_verified` или `project_approved` описывают **записи ревью в IML**, а не рецензируемую науку.

## Минимум provenance

В экспорте по возможности сохраняйте:

- контрольную сумму входа и сводку аудита импорта;
- версию приложения **1.1.1**;
- ID профиля прибора и статус верификации;
- версию rule pack, ID правил и пороги;
- параметры методов и число воздержаний;
- коды решения эксперта с обоснованием и временными метками.

## Воздержание и Indeterminate

**Abstention** (метод/правило отказывается от метки) и **Indeterminate** (решение эксперта) — допустимые научные исходы. Их нельзя молча заменять метками по умолчанию в отчётах.

## Тестирование vs валидация

| Действие | Что показывает | Чего не показывает |
|----------|----------------|---------------------|
| Rule Testing Lab на dev-выборке | Поведение реализации vs метки | Перенос на другие станции/эпохи |
| Внутренний pytest | Регрессии кода | Геофизическую истину |
| Синтетические учебные данные | UI и код | Операционный прогноз ионосферы |

## Участие человека

Экспертная проверка (**Accept**, **Change**, **Indeterminate**, **N/A**) — отдельная ось. В публикациях указывайте и автоматические кандидаты, и решения эксперта.
