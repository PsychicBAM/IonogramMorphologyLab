# Полное руководство пользователя — 1.1.1

Описание текущего настольного интерфейса. Ниже — английские подписи кнопок; при языке **Русский** элементы локализованы. Все автоматические результаты трактуйте как **кандидатные предложения**, а не финальную науку.

## Предварительные условия

- Обрабатывайте только разрешённые файлы.
- Используйте writable workspace вне каталога установки.
- Сохраняйте идентификаторы источника, метаданные профиля и предупреждения аудита в журнале исследования.
- Производный кэш Zarr **не** является исходной записью.

## Десять учебных примеров (Tutorial)

### Учебный пример 1 — Создание прослеживаемого проекта

1. На **Home** выберите **New Project**, введите имя, укажите папку workspace, нажмите **Create**.
2. Зафиксируйте путь workspace и ID проекта в журнале.
3. Не импортируйте исследовательские MAT, пока не отработаете synthetic.

### Учебный пример 2 — Импорт и аудит MAT

1. **Import Data** → **Import MAT file**, выберите разрешённый файл.
2. Проверьте **Data Audit** до продолжения — сохраните точный текст предупреждений.
3. Сверьте переменную, форму и временной охват с документацией прибора.

### Учебный пример 3 — Профиль прибора

1. **Instrument Profile** — мастер или bundled-профиль.
2. **Verification status** указывайте честно (`provisional` до экспертного ревью).
3. **Save profile** — не подавляйте предупреждения без записи в журнале.

### Учебный пример 4 — Навигация по кадрам

1. **Viewer** — выбор кадра, **Previous/Next**.
2. Метаданные и масштаб; при необходимости **Build cache** для Zarr.
3. Просмотрите несколько кадров для проверки ориентации.

### Учебный пример 5 — Пакетный анализ

1. **Batch Analysis** — область, профиль, версии rule pack.
2. **Start**, дождитесь завершения.
3. **Results** — кандидаты по отдельным осям.

### Учебный пример 6 — Проверка предложений морфологии

1. В **Results** выберите строку, сравните overlay с кадром.
2. **Expert Review** для значимых кадров.
3. Обоснование при переопределении автоматических кандидатов.

### Учебный пример 7 — Параметры ионограммы

1. **Ionogram Parameters** → **Load from last result**.
2. Единицы, метод, поля неопределённости.
3. **Accept**, **Reject** или **Indeterminate**, затем **Save expert edits**.

### Учебный пример 8 — Правило без кода

1. **Rule Builder** → **New rule**, пройдите страницы мастера.
2. **Preview generated code** — ветки abstention.
3. **Save rule** — версионированный snapshot YAML.

### Учебный пример 9 — Тест правила по меткам

1. **Rule Testing Lab** — версия правила и размеченный набор.
2. Зафиксируйте split, метрики и optional threshold sweep.
3. **Run test**, разбор ошибок в **Viewer**, экспорт записи прогона.

### Учебный пример 10 — Воспроизводимый отчёт

1. **Reports** — язык и поля provenance.
2. **Export** (CSV, JSON, HTML, Markdown).
3. Архивируйте отчёт с manifest проекта и версией профиля.

## Результаты и provenance

Читайте результат вместе с контрольной суммой входа, версией ПО **1.1.1**, ID профиля, идентификаторами методов/правил, порогами, метками времени и решением эксперта. **Indeterminate** — допустимый исход, а не «ошибка», которую нужно скрыть.

## Защита данных

Приложение локальное, но хранилище на диске подчиняется политикам доступа организации. Не включайте ограниченные кадры в issues, скриншоты и примеры экспорта без редактирования.
