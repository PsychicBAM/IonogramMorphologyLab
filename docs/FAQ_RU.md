# FAQ — 1.1.1

Частые вопросы о возможностях, ограничениях и развёртывании Ionogram Morphology Lab.

## Устанавливает ли приложение физический механизм?

Нет. IML формирует **кандидатные** предложения морфологии и параметров, согласованные с изображением. Нужны экспертный контекст, знание прибора и независимая валидация. Успешный прогон конвейера — не утверждение о механизме.

## Нужен ли MATLAB?

Нет. **MATLAB Studio** опционален. Импорт, просмотр, пакетный анализ, экспертная проверка, тестирование правил (без внешних script-backend) и отчёты работают без MATLAB и Octave. CI на Ubuntu MATLAB не устанавливает.

## Изменяются ли исходные MAT?

В обычном режиме исходный MAT **только для чтения**. Производные артеfactы — кэш Zarr, JSON проекта, отчёты, YAML правил, joblib Model Lab — отделены. В пакет проекта исходный MAT по умолчанию не включается.

## Можно ли использовать пользовательские правила в публикации?

Только после документирования происхождения (provenance), области применимости, порогов, протокола тестирования и независимой валидации. Статус правила в ПО (`draft`, `project_approved` и т.д.) **не** является научной валидацией.

## Что означают Accept, Change, Indeterminate и N/A в Expert Review?

Это **коды решения эксперта** в audit trail:

| Код | Смысл |
|-----|--------|
| **Accept** | Согласие с автоматическим кандидатом для кадра |
| **Change** | Переопределение метки; обязательно обоснование |
| **Indeterminate** | Недостаточно evidence для обоснованной метки |
| **N/A** | Кадр не относится к вопросу исследования |

В интерфейсе сохраняются английские токены для воспроизводимости; в отчётах можно давать пояснение по-русски.

## Передаются ли данные в сеть?

Телеметрия по умолчанию **выключена**. ОС, резервное копирование и политики организации по-прежнему определяют среду.

## Можно ли считать предсказания Model Lab операционными?

По умолчанию нет. Model Lab — **разработческий** workflow. Нужны holdout, внешняя валидация и governance до любых операционных заявлений.

## Что такое provenance в IML?

Provenance связывает результаты с контрольными суммами входов, версией ПО, профилем прибора, ID пакетов правил, параметрами методов и решениями эксперта. Это прослеживаемость, а не замена peer review.

## Почему учебные скриншоты синтетические?

PNG в документации сняты только с **учебных синтетических проектов** (`synthetic_data/`). Схематические SVG-макеты — в `docs/assets/schematics/`.

## Можно ли разрабатывать на Linux?

Да. Установка из исходников: Python 3.10+ и `pip install -e ".[dev]"`. Основной end-user target — Windows portable; CI на Ubuntu без MATLAB и дисплея.

## Где хранятся схематические диаграммы?

SVG-макеты — в `docs/assets/schematics/`. Их пересоздаёт `scripts/generate_doc_screenshots.py`. Они не заменяют PNG-скриншоты UI.

## Как проверить документацию перед PR?

Запустите `python scripts/validate_docs.py` вместе с `validate_readme.py` и `check_repository_hygiene.py` — те же проверки, что в GitHub Actions.
