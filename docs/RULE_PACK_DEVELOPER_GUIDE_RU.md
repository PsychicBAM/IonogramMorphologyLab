# Руководство разработчика пакетов правил

## Структура пакета
Размещайте пакет в `rule_packs/<pack-id>/`:

```text
pack.yaml
rules/<rule-id>.yaml
README_EN.md
README_RU.md
```

Для `pack.yaml` обязательны `pack_id` и `version`. Каждое правило загружается как `ScientificRule`; неизвестные поля игнорируются для совместимости, но научные метаданные нельзя опускать только ради успешной загрузки.

## Правила
Храните отдельно выходы слоя, морфологии, неоднозначности, качества и параметров. Указывайте применимость, исключения, альтернативы, ограничения, источники, печатные/PDF-страницы, происхождение порога и статусы. Не придумывайте буквенные подтипы Es: используйте только прослеживаемые записи из `ES_SUBTYPE_SOURCE_REGISTRY.csv`.

## Проверка и установка
Выполняйте `validate_pack()` перед распространением. Импорт ZIP проверяет абсолютные пути и обход каталогов, а повреждённые архивы изолируются. Неудачный импорт не должен менять установленные пакеты. Проверяйте enable/disable на временной папке пакетов.

## Фильтрация статусов
Scientific Strict использует `filter_rules_by_status()` и показывает только допустимые утверждённые/source-verified статусы. Автор не должен повышать правило лишь потому, что оно запускается, согласуется с другим методом или проходит синтетический тест.

## Воспроизводимость
Версионируйте правила, документируйте изменения, сохраняйте ссылки и права, фиксируйте признаки и область профиля. Явно указывайте, что перебор порогов и синтетика — проверки разработки, а не научная валидация.
