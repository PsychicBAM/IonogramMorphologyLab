# FAQ — 1.1.1

Frequently asked questions about Ionogram Morphology Lab capabilities, limits, and deployment.

## Does the application identify physical mechanisms?

No. IML produces **candidate** morphology and parameter proposals compatible with image evidence. Expert context, instrument knowledge, and independent validation remain necessary. A successful pipeline run is not a mechanism claim.

## Is MATLAB required?

No. **MATLAB Studio** is optional. Core import, viewing, batch analysis, expert review, rule testing (without external script backends), and reporting work without MATLAB or Octave. CI on Ubuntu does not install MATLAB.

## Are source MAT files changed?

Normal workflows treat source MAT as **read-only**. Derived artifacts — Zarr cache, project JSON, reports, rule YAML, Model Lab joblib — are separate. Packaging excludes source MAT by default.

## Can I use custom rules in a publication?

Only after documenting provenance, applicability, thresholds, testing protocol, and independent validation. A rule’s software status (`draft`, `project_approved`, etc.) is **not** scientific validation.

## What do Accept, Change, Indeterminate, and N/A mean in Expert Review?

These are **expert decision codes** stored in the audit trail:

| Code | Meaning |
|------|---------|
| **Accept** | Agree with the automatic candidate for this frame |
| **Change** | Override with a different label; rationale required |
| **Indeterminate** | Evidence insufficient for a defensible label |
| **N/A** | Frame not applicable to the study question |

They are UI identifiers; translate them in reports but keep the stored token for reproducibility.

## Is data sent over the network?

No telemetry is enabled by default. Your OS, backup tools, and institutional policies still govern the wider environment.

## Can Model Lab predictions be treated as operational products?

Not by default. Model Lab is a **development** workflow. It requires appropriate holdout design, external validation, and governance review before any operational claim.

## What is provenance in IML?

Provenance links outputs to input checksums, software version, instrument profile, rule pack IDs, method parameters, and expert decisions. It supports traceability; it does not replace peer review.

## Why are teaching screenshots synthetic?

Documentation PNG captures use **synthetic teaching projects only** (`synthetic_data/`). They illustrate UI layout without private ionograms or local usernames. Schematic SVG mocks live under `docs/assets/schematics/`.

## Where is version 1.1.1 documented?

See [CHANGELOG.md](../CHANGELOG.md), About dialog, and [Documentation file audit](DOCUMENTATION_FILE_AUDIT.md).

## Can I run IML on Linux for development?

Yes. Install from source with Python 3.10+ and `pip install -e ".[dev]"`. The primary supported end-user target remains Windows portable; CI runs pytest on Ubuntu without MATLAB or a display.

## Where are schematic diagrams stored?

SVG layout mocks live in `docs/assets/schematics/`. They illustrate component placement and are regenerated by `scripts/generate_doc_screenshots.py`. They are not substitutes for PNG UI captures.

## How do I validate documentation locally before a PR?

Run `python scripts/validate_docs.py` together with `validate_readme.py` and `check_repository_hygiene.py`. These checks mirror the GitHub Actions test workflow.
