# Быстрый старт — 1.1.1

Краткое руководство по **первой успешной сессии** в Ionogram Morphology Lab (IML). Нужны доступная для записи папка проекта и данные, которые вам разрешено обрабатывать.

> **До исследовательских данных:** используйте учебные файлы [`synthetic_data/`](../synthetic_data/). Они проверяют интерфейс и конвейер, но **не** доказывают научный вывод и совместимость с MAT вашей станции.

## Предварительные условия

- Установлен IML **1.1.1** (portable или `pip install -e ".[dev]"` из исходников).
- Отдельная папка проекта с местом под производный кэш (Zarr) и отчёты.
- По желанию: [Установка](INSTALLATION_RU.md).

## Шаг 1 — Язык и первый запуск

1. Запустите приложение.
2. В диалоге первого запуска выберите **English** или **Русский**.
3. Смена языка: **Settings → General → Interface language**.

## Шаг 2 — Создание проекта (Home)

1. Откройте **Home**.
2. **New Project** — имя и **папка workspace** (доступна для записи, вне каталога установки).
3. Изучите полосу **рекомендуемого workflow** (цвета статусов шагов).
4. При необходимости выберите **UX mode**:
   - **Guided** — минимум продвинутых элементов;
   - **Research** — инструменты сравнения и анализа;
   - **Expert** — полное меню, включая Rule Builder и Model Lab.
5. **Continue recommended step** — переход к следующему незавершённому шагу.

![Home](../assets/screenshots/home_ru.png)

*Alt: панель Home с рекомендуемым workflow и выбором UX-режима.*

## Шаг 3 — Импорт MAT

1. **Import Data** (или следующий шаг с Home).
2. **Import MAT file** или **Import Folder**.
3. Для первого запуска — файл из `synthetic_data/`.
4. **Data Audit** — проверьте:
   - имя переменной и форму массива;
   - число кадров и временной охват;
   - ориентацию частотной оси.
5. При предупреждениях аудита — устраните или задокументируйте их до пакетного анализа.

![Import Data](../assets/screenshots/data_audit_ru.png)

*Alt: Import Data со сводкой Data Audit.*

## Шаг 4 — Профиль прибора

1. **Instrument Profile**.
2. Выберите bundled-профиль или мастер для новой станции.
3. **Verification status** указывайте честно: *provisional* / *user-defined-unverified* до экспертного подтверждения.
4. Сохраните профиль в проект.

Неверные частотные/высотные параметры дают ошибочные предложения морфологии.

## Шаг 5 — Viewer и кэш

1. **Viewer** — выберите кадр.
2. Просмотрите изображение и метаданные.
3. **Build cache** — производный Zarr-кэш; **исходный MAT не изменяется**.
4. Просмотрите несколько кадров для проверки ориентации.

Без кэша последующие шаги могут быть заблокированы (Home покажет предупреждение).

## Шаг 6 — Пакетный анализ

1. **Batch Analysis** — проверьте область и версии правил.
2. **Start**, затем **Results**.

Результаты — **кандидатные предложения**:

| Понятие | Смысл |
|---------|--------|
| Качество данных | Пригодность кадра |
| Candidate morphology | Метка по изображению — не подтверждённая физика |
| Альтернативы | Неоднозначность и флаги |
| Auto status | Уверенность / abstention |

## Шаг 7 — Экспертная проверка

1. **Expert Review**.
2. **Accept** (принять) / **Change** (изменить) / **Indeterminate** (неопределённо) / **N/A** (не применимо) — коды решения эксперта в audit trail.
3. Обязательное **обоснование** при переопределении.
4. **Save expert edits**.

## Шаг 8 — Экспорт отчётов

1. **Reports** — язык EN/RU, форматы CSV/JSON/HTML/Markdown.
2. **Export** в `exports/`.
3. Сохраните вместе с manifest, профилем и версиями rule pack.

Проверьте отчёты перед публикацией — возможны локальные пути из сессии.

## Безопасная работа

| Делайте | Избегайте |
|---------|-----------|
| MAT только для чтения | Перезапись оригиналов |
| Сначала synthetic | Импорт ограниченных данных без разрешения |
| Явный provisional | «Verified» без проверки |
| Provenance с экспортом | Публикация без редактирования путей |

[Научные ограничения](SCIENTIFIC_LIMITATIONS_RU.md).
